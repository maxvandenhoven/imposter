# Imposter

LLM agents from different model families (Gemini, Claude, open models on Vertex AI) play
the social deduction game [Imposter](https://imposter.app/) against each other. A demo for
exploring Google's Agent Development Kit (ADK), deployment on GCP (Cloud Run, IAP,
Terraform) and tracing (OpenTelemetry, Cloud Trace).

## Play a game

With `.env` set up (see below), `make play` runs a game in the terminal between a mixed
lineup of models and prints the outcome, the debrief and the token cost. Options go in
`ARGS`, for example `make play ARGS="--god --word lighthouse -p gemini-flash -p
claude-haiku -p gpt-oss"`, where `--god` also shows the secret word, the roles and every
private reasoning. `uv run imposter play --help` lists every option. `make adk-web`
starts the ADK developer UI, in which every new session plays a game.

## Web app

`make dev` starts the game API on port 8000 and the web app on
[localhost:5173](http://localhost:5173), which reloads as its code changes. On the setup
screen you choose how the secret word is picked (at random from a category, a custom word
with an optional category of your own, or generated by Gemini), the model behind each of 3
to 8 seats, which players are the imposters (one random seat to begin with, or shuffled
with "Randomise imposters"), the order of the seats, which can be dragged by their
handles, how players are named and the other options, and the screen checks the options
before the game can start. Below the setup, "How to play" explains every phase of the game
with small illustrated scenes of players, speech bubbles and ballots, which mark allowed
answers with a check and rule breaking ones with a cross. The board then shows the game
with a table card across the top and the players in a row below it, in seat order, with
the transcript of every clue and statement next to it. In clue, discussion and guess turns
the answer is written out on the table and then moves down into the player's column, with
the player's private reasoning in a thought bubble below it. When the votes are revealed,
each vote flies as a ballot with the voter's name from the voter's card to the card of the
player it is for and stays there, followed by the imposter's guess with the judge's
verdict and a dark banner with the outcome. The dark header bar across the top shows the
phase, the tokens and estimated cost so far and a link to the game's trace in Cloud Trace.
Every phase that has ended in the header can be clicked to jump to the end of that phase,
so it can be discussed.

The board plays the game at a pace the audience can follow rather than as fast as the
models answer: answers are written out at a steady rate and every clue, statement and
reveal stays long enough to be read. A playback bar pauses and resumes, steps through
the events and phases, pauses after each round and changes the speed. While playback is
behind the live game it speeds up smoothly to catch up, and "Go live" jumps to the
newest state.

The board has two modes, switched with "Show hidden info" in the view settings of the
header, and showing the hidden info is the default. Audience mode shows only what the
players could see, and keeps the secret word, the roles, the secret votes, the private
reasoning and the models' own thinking hidden until the reveal, also in answers that are
still being written. With hidden info shown the board shows everything: the word on the
table, a role badge on every seat and each player's private reasoning as a thought bubble
while it is written. The game runs as long as the page is open, so the page asks before it
is left, and leaving or stopping it aborts the game. The header exports the game as JSON,
which the setup screen can import to replay it, and a debrief panel follows a finished
game.

The web app is a React app in `frontend/` (Vite, TypeScript, Tailwind CSS and
shadcn/ui). `make frontend` builds it into `frontend/dist`, which the API app then serves
at `/`, so the built app and the API share one origin on port 8000. Its TypeScript types
of the API, the game request and the game events are generated from the app's OpenAPI
schema with `make api-client`.

## Container

The `Dockerfile` builds the image that runs the app: a Node stage builds the web app, a
uv stage installs the package, and a slim Python image serves both with uvicorn on
`$PORT` (8080 by default). `make docker` builds the image and runs it on
[localhost:8080](http://localhost:8080) with `.env` and the gcloud application default
credentials mounted, so a real game plays in the container.

## Deploying

After the one-time setup in [`docs/setup.md`](docs/setup.md), `make up` creates the
infrastructure with Terraform, builds the image in Cloud Build and deploys it to Cloud Run
in `europe-west4`. The service sits behind IAP, which only lets in the principals in `iap_members`, and
`make smoke` prints a checklist for trying it. `make deploy` ships a
new version, `make down` removes everything Terraform manages and `make nuke` also removes
the state bucket. [`docs/infrastructure.md`](docs/infrastructure.md) lists the resources,
their costs and how to roll back.

## Game API

The backend is ADK's own API server for the game app, plus a `/catalog` route that lists
the models, the word categories and the default lineup, and a `/traces/{game_id}` route
with the Cloud Trace link of a game. A game is an ADK session: the client creates a
session with the game options in its state, then plays it with `POST /run_sse`, which
streams the game while it runs. Every game event comes as an ADK event with the event in
its custom metadata, a "turn started" event says whose turn it is before the model
answers, and with `"streaming": true` every answer streams token by token as it is
written. The game runs as long as that request is open and is aborted when the client goes
away. [`docs/plans/web-ui.md`](docs/plans/web-ui.md) describes the stream in detail.

## How a game runs

A pure game engine owns the rules and the event log, and decides every phase change. The
game is played by an ADK graph workflow that uses only ADK's own building blocks. Five
plain functions are its nodes, in a loop: `setup` chooses the word and creates the game,
`next_turns` starts the next turn, or all turns at once for the votes and the debrief,
`play_turn` asks one player per started turn, `apply_turns` applies the answers to the
game, and `finish` ends the run when the engine says the game is over. `play_turn` is a
parallel worker, so ADK runs the turns of a parallel phase at the same time.

The game itself lives in the state of its ADK session, as a snapshot of the setup and the
event log, and every engine event is also an ADK event in the stream. A player is a plain
ADK `LlmAgent` that runs inside the same run as a child of its turn, so its answer
streams to the browser and its model call is part of the game's trace. The agent gets
nothing but the prompt rendered from what its seat may see: no conversation history and
nothing from the session state, which holds the secret word. ADK validates each answer
against the schema of the phase and retries the agent when the answer does not match.

A judge decides what code cannot: whether a guess is a synonym of the word, and whether a
clue is a trivial derivative of it. It asks yes or no questions through ADK's classifier
interface and reads the answer as a probability. With an API key for the Gemini Developer
API in `GEMINI_API_KEY`, the questions go to the Gemini Decisions API, a model made for
such decisions. Without the key they go to Gemini Flash-Lite on Vertex AI.

In the ADK developer UI (`make adk-web`), the graph shows the loop and highlights the
node of the selected event.

## Tracing

Every game is one trace in Cloud Trace. ADK traces the workflow and every node, so the
trace has a root span for the game, a span per step of the loop and a span per turn. ADK
also traces every model call, with its token usage, and below it every HTTP attempt of
the call is a span with its status code, so retries after a timeout or a rate limit are
visible. The app puts the phase, the round and the player on ADK's span of each turn and
adds a span per judge decision, with a span for the call to the Gemini Decisions API
below it, and the model calls of the players nest under their turn. The root span
carries the lineup and the outcome, and the secret word only as a hash, so a list of
traces does not spoil it. `make play` prints the Trace Explorer link of the game when
it ends.
